# নিরাপত্তা মডেল

## ১. কী কোথায় থাকে (secret ম্যাপ)
| তথ্য | কোথায় | GitHub/ব্রাউজারে? |
|---|---|---|
| `TOKEN_SECRET` (সেশন টোকেন সই করার কী) | Apps Script **Script Properties** | ❌ কখনও না |
| ইউজারের পাসওয়ার্ড | শুধু হ্যাশ (`pbk1$…` — ব্যক্তিগত salt + ১০০০ ধাপ HMAC-SHA256), Sheet-এর `Users` tab-এ | ❌ হ্যাশও ব্রাউজারে যায় না |
| Google OAuth টোকেন/ক্লায়েন্ট সিক্রেট/service-account | **নেই** — স্ক্রিপ্ট মালিকের অনুমতিতে (`Execute as: Me`) চলে, ব্রাউজার Google API সরাসরি ডাকে না | — |
| Web App URL | `config.js` / GitHub variable | ✅ প্রকাশ্য (গোপন নয়, একা কিছুই খোলে না) |
| সেশন টোকেন (১২ ঘণ্টা) | ব্রাউজারের `sessionStorage` (ট্যাব বন্ধ = শেষ) | শুধু ব্যবহারকারীর ব্রাউজারে |

## ২. প্রতিটি অনুরোধে সার্ভারে যা যাচাই হয়
1. **টোকেন**: HMAC স্বাক্ষর, মেয়াদ, এবং `tokenVersion` (পাসওয়ার্ড/রোল/active বদলালে পুরোনো সেশন সাথে সাথে বাতিল)।
2. **রোল ও active** — টোকেনে নয়, প্রতি অনুরোধে Sheet থেকে নতুন করে পড়া হয় (ইউজার disable করলে তৎক্ষণাৎ কার্যকর)।
3. **অনুমতি ম্যাট্রিক্স** (নিচে) — টেবিল × ক্রিয়া (read/create/update/delete) × রোল।
4. **প্রজেক্ট-স্কোপ**: Super Admin বাদে কেউ শুধু নিজের তৈরি বা সদস্য-করা প্রজেক্ট ও তার সব সন্তান (ফ্লোর, রুম, পয়েন্ট, ফিক্সচার, সার্কিট, এস্টিমেট, BOQ override, ড্রয়িং, কোটেশন, PO, ফাইল) দেখতে/বদলাতে পারে। `projectId` সন্তান-রেকর্ডে সার্ভার নিজে বের করে — ক্লায়েন্টের পাঠানো মান উপেক্ষিত।
5. **ভ্যালিডেশন**: প্রতিটি কলামের টাইপ, দৈর্ঘ্য, সীমা, enum, unique, foreign key; অজানা/লুকানো ফিল্ড বাদ; বাতিল বা অর্ধেক লেখা এড়াতে batch পুরোটা “সব-নয়-তো-কিছুই-না”।
6. **Formula injection**: String কলাম plain-text ফরম্যাটে; `=HYPERLINK(...)` লিখলেও তা সূত্র হিসেবে চলে না।
7. **Duplicate submission**: প্রতিটি লেখার `reqId`; একই `reqId` আবার এলে সার্ভার আগের ফল ফেরত দেয়, আবার চালায় না।
8. **Conflict**: `rev` মেলে না → `CONFLICT` (অন্য কেউ ইতিমধ্যে বদলেছে); ড্রয়িংয়ের জন্যও একই।
9. **Rate limit**: প্রতি ইউজার প্রতি মিনিটে ২৪০ অনুরোধ; লগইনে একই ইমেইলে ৫ বার ভুলের পর ১৫ মিনিট লক।
10. **একসাথে লেখা**: Script Lock — একটি সময়ে একটিই লেখা চলে, তাই কাউন্টার/নম্বর/কোটেশন-নম্বরে race হয় না।
11. **Attribution**: `userName`, `createdBy`, `changedBy` সবসময় সেশন থেকে — ক্লায়েন্ট মিথ্যা নাম পাঠালেও লাগে না।
12. **ফাইল**: রোল+ক্যাটেগরি, প্রজেক্ট-সদস্যতা, এক্সটেনশন allow-list, ম্যাজিক-বাইট যাচাই (`.png` নামে .exe আটকায়), ≤ ৮ MB; Drive-এ `PRIVATE`; ডাউনলোডও অনুমতি যাচাই করে ডেটা স্ট্রিম করে।
13. **Audit log**: লগইন (সফল/ব্যর্থ), সব মুছে ফেলা, প্রজেক্ট/কোটেশন/ম্যাটেরিয়াল/সাপ্লায়ার/ইউজার/সেটিং পরিবর্তন, ফাইল আপলোড/মুছা, স্টক মুভমেন্ট, ড্রয়িং সেভ, ব্যাকআপ, ব্যর্থ ব্যাকআপ, রিস্টোর, মাইগ্রেশন। শুধু Super Admin পড়তে পারে; কেউ মুছতে/বদলাতে পারে না (restore-ও না)।
14. **Viewer-এর খরচের তথ্য**: VIEWER-এর কাছে কোটেশনের `totalCost` ও লাইন-আইটেমের ক্রয়মূল্য সার্ভার থেকেই পাঠানো হয় না।

## ৪. Google সেটআপ সংক্রান্ত নিরাপত্তা নির্দেশ
* ডেটা-মালিক Google অ্যাকাউন্টে **২-ধাপ যাচাই (2-Step Verification)** চালু করুন — এই অ্যাকাউন্ট ও তার Sheet/Drive-ই আসল ভল্ট।
* `Website_Data` ফোল্ডার বা `EFBMS_Database` Sheet **কারও সাথে share করবেন না**, “Anyone with the link” করবেন না। (অ্যাপ সব ফাইল গেটওয়ের মাধ্যমে দেয়।)
* Apps Script প্রজেক্টের Editor-অ্যাক্সেস শুধু বিশ্বস্ত ব্যক্তিকে দিন — Editor Script Properties (`TOKEN_SECRET`) পড়তে পারে।
* সন্দেহ হলে সব সেশন বাতিল করতে: Script Properties-এ `TOKEN_SECRET` মুছে `setup()` চালান (নতুন secret তৈরি হবে; সবাই আবার লগইন করবে)।

## ৫. সততার সঙ্গে: অবশিষ্ট ঝুঁকি ও সীমাবদ্ধতা
* **Web App “Anyone”**: এন্ডপয়েন্ট ইন্টারনেট থেকে ডাকা যায়। brute-force ঠেকাতে লক+rate-limit আছে, কিন্তু Apps Script-এর `CacheService` “best-effort” — পাকা firewall নয়। তাই **দীর্ঘ পাসওয়ার্ড** ব্যবহার করুন (সিস্টেম ≥ ৮ অক্ষর বাধ্য করে, সাধারণ পাসওয়ার্ড আটকায়)।
* **লগইন-লক নিজেই DoS হতে পারে**: কেউ ইচ্ছাকৃতভাবে কারও ইমেইলে ভুল পাসওয়ার্ড দিয়ে ১৫ মিনিট লক করে রাখতে পারে (আপনার ইমেইল জানা থাকলে)। এটি brute-force রোধের বিনিময়-মূল্য।
* **পাসওয়ার্ড হ্যাশ**: Apps Script-এ native PBKDF2/bcrypt নেই; ১০০০ ধাপ HMAC-SHA256 + ব্যক্তিগত salt ব্যবহার করা হয় (গতির সীমার কারণে)। আধুনিক নীতির চেয়ে কম ধাপ — Sheet ফাঁস হলে offline অনুমান সম্ভব, তাই Sheet-এর সুরক্ষা (উপরে ৪) জরুরি।
* **টোকেন `sessionStorage`-এ**: ব্রাউজারে XSS হলে চুরি সম্ভব। এড়াতে: কোনো তৃতীয়-পক্ষ স্ক্রিপ্ট নেই এবং বিল্ডে কড়া **Content-Security-Policy** (`script-src 'self'`; `connect-src` শুধু `script.google.com`) যুক্ত। GitHub Pages HTTP header দিতে পারে না, তাই CSP `<meta>` হিসেবে; `frame-ancestors` (clickjacking) meta-তে কাজ করে না।
* **এস্টিমেশন/BOQ গণনা ব্রাউজারে চলে**: একজন বৈধ লগইন-করা ENGINEER নিজের প্রজেক্টের এস্টিমেট-সারিতে ভুল সংখ্যা লিখতে পারে (সার্ভার টাইপ/সীমা যাচাই করে, সূত্র নয়)। তার ক্ষতি তার সদস্য-প্রজেক্টেই সীমিত। **কোটেশনের মোট অঙ্ক সার্ভারে পুনর্গণনা হয়** এবং তৈরির পর অপরিবর্তনীয়।
* **ম্যাটেরিয়ালের ক্রয়মূল্য** VIEWER-ও ম্যাটেরিয়াল লাইব্রেরিতে দেখতে পায় (আগের সাইটের মতোই; BOQ খরচ ক্লায়েন্টে গণনা হয় বলে)। কোটেশনের খরচ লুকানো আছে।
* **Quota**: Apps Script/Drive-এর দৈনিক সীমা আছে (ফ্রি অ্যাকাউন্টে কম, Workspace-এ বেশি; সংখ্যা Google বদলায়)। ছোট দল (প্রায় ১০–২০ জন একসাথে) ও মাঝারি ডেটার জন্য উপযুক্ত। প্রতিটি কল সাধারণত ১–৩ সেকেন্ড।
